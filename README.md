# UZEX Spot AI — ИИ-агент реестра биржевых сделок (`spot.uzex.uz`)

Двуязычный (**Русский / O‘zbek tili — лотин ва кирилл**) интеллектуальный ИИ-агент (Веб-сервис FastAPI + Streamlit-интерфейс + Telegram-бот) для точных ответов по реестру биржевых сделок УзРТСБ (`spot.uzex.uz`, январь 2022 — октябрь 2026: **500 000 сделок, 6 616 контрактов, 14 392 участника, 120 брокеров, 1 765 курсов USD**).

---

## 📋 Описание решения (готовый текст для формы сдачи — 20 баллов)

> **Ниже приведено структурированное описание технологий, архитектуры, нормализации данных и методики верификации ответов, которое можно напрямую использовать в форме сдачи проекта.**

### 1. Технологический стек и архитектура
Решение построено по архитектуре **Multi-Step Grounded Text-to-SQL Agent с детерминированной верификацией чисел (Zero-Hallucination Engine)**:
- **Аналитическая СУБД**: **DuckDB** (колоночное хранение, векторное выполнение агрегаций по 500 000 сделкам за **5–25 мс**).
- **LLM и агентный контур**: **Google Gemini Flash (`google-genai` SDK)** с `temperature=0.0`, управляемым бюджетом рассуждений (`thinking_budget`) и **Function Calling** (`find_entity`, `run_sql`), объединённый в отказоустойчивый пул моделей и API-ключей с автоматическим failover.
- **Безопасность и валидация SQL**: **SQLGlot** — AST-парсер, гарантирующий выполнение только read-only `SELECT`-запросов строго к разрешённым таблицам реестра.
- **Интерфейсы**:
  1. **Веб-сервис (FastAPI + Vanilla JS/CSS)** с потоковой передачей шагов рассуждения (NDJSON streaming), отображением каждого выполненного SQL-запроса, интерактивными таблицами с выгрузкой в CSV, встроенной визуализацией и аналитическим дашбордом.
  2. **Streamlit-приложение (`src/app.py`)** и **Telegram-бот (`src/bot.py`, `aiogram 3.x`)**, использующие единое ядро агента.

### 2. Глубокая очистка и 100% каноническая нормализация данных (`src/normalize.py`, `src/build_db.py`)
При исследовании сырых CSV-файлов были выявлены и решены ключевые проблемы качества данных, без устранения которых прямые SQL-запросы дают заниженные или неверные ответы:
1. **Скрытые в тексте атрибуты товаров (697 уникальных комбинаций → 41 канонический товар, 0 пропусков)**:
   - В `contracts.csv` и `deals_*.csv` одно и то же семейство товара записано десятками способов: например, *«Бензин»*, *«Бензин АИ-80»*, *«Бензин АИ-92»*, *«Мука пшеничная В/С»*, *«Мука пшеничная 1-сорт»*, *«Цемент ПЦ 400»*, *«Цемент ЦЕМ I 42,5Н»*, *«Арматура А500С Ø12 мм»*. При этом поля `Марка`, `Сорт`, `Класс`, `Размер`, `Тип` в карточке контракта часто оставлены пустыми (`NULL`), когда продавец указал их прямо в названии товара.
   - Разработан детерминированный нормализатор `src/normalize.py` (`family_of`, `brand_of`, `size_of`, `sort_of`, `type_of`, `class_of`), который сопоставляет все **697** комбинаций карточек контрактов и названий сделок в **41 каноническое семейство** (`product_family` на русском и `product_family_uz` на узбекском) и извлекает `brand_norm`, `sort_norm`, `class_norm`, `size_norm`, `type_norm` со **100% полнотой (0 пустых значений)**.
2. **Двуязычие регионов и типографские апострофы**:
   - В таблицах `deals`, `participants`, `brokers` регионы записаны на узбекской латинице с типографским апострофом `‘` (U+2018), например `Farg‘ona viloyati`, `Qoraqalpog‘iston Respublikasi`, а в `contracts.csv` — на русском (`Ферганская область`, `Республика Каракалпакстан`).
   - При сборке БД апострофы нормализуются к единому виду, а во все таблицы (`deals`, `contracts`, `participants`, `brokers`) добавлены оба поля: `region` (UZ) и `region_ru` (RU).
3. **Кросс-скриптовый и фонетический поиск компаний и брокеров (`entity_index`)**:
   - Названия участников (14 392) и брокеров (120) в реестре записаны в разных алфавитах (узбекская латиница, узбекская кириллица с `Ў/Қ/Ғ/Ҳ`, русская кириллица) и с разными ОПФ (`MChJ`, `МЧЖ`, `ООО`, `ҚК`, `ХК`, `АЖ`, `ЧП`).
   - Построен индекс `entity_index` с двумя ключами: `translit_key` (очистка кавычек и ОПФ + транслитерация кириллица↔латиница) и `phonetic_key` (фонетическая унификация пар `q/k`, `h/x`, `o‘/u/o`, `ts/s`) + метрика сходства **Jaro-Winkler** в DuckDB. Благодаря этому русскоязычный запрос *«Сотото Металл»* или *«Пудексиз Пласт»* безошибочно находит `"СОТЎТО МЕТАЛЛ" МЧЖ (ИНН 917899526)` и `"PUDEXIZ PLAST" MCHJ (ИНН 975923536)`.
4. **Валюты (`UZS` / `USD`), единицы измерения и дисциплина исполнения**:
   - Все 493 410 внутренних сделок заключены в `UZS`, а 6 590 экспортных сделок (*Катод медный* и *Пряжа хлопчатобумажная*) — в `USD`. В денормализованной таблице `deals` предрассчитаны как `amount_uzs` (по курсу `usd_rates` на дату сделки), так и `amount_usd`.
   - Учтено, что *Бензин* торгуется в `тоннах` и `литрах`, а *Дизельное топливо* — в `тоннах` и `килограммах` — агент группирует физические объёмы и средние цены по `unit`.
   - Предрассчитаны флаги просрочки оплаты (`is_late_payment`: `payment_days > payment_term_days` — 0 сделок) и просрочки поставки (`is_late_delivery`: `delivery_days > delivery_term_days` — 17 805 сделок), а также сохранены все 6 616 контрактов (включая 133 контракта без сделок) и все 14 392 участника (включая 3 покупателей без сделок).

### 3. Как мы проверяли ответы и защищали агента от галлюцинаций
1. **Запрет вычислений «в уме» LLM**: модель не имеет права придумывать числа или считать суммы/доли самостоятельно — все расчёты выполняются через инструмент `run_sql` в DuckDB.
2. **Автоматический верификатор чисел (`ungrounded_numbers` в `src/agent.py`)**:
   - После генерации ответа парсер извлекает из текста все числовые утверждения (с учётом пробелов-разделителей тысяч, запятых и множителей *тыс./млн/млрд/трлн/%*) и сверяет каждое число с массивом фактических чисел, возвращённых SQL-запросами в текущей сессии.
   - Если в ответе обнаружено хотя бы одно неподтверждённое число, верификатор блокирует ответ и запускает шаг самокоррекции (`VERIFIER retry`), требуя пересчитать значение через `run_sql` или удалить его.
3. **Честный отказ при отсутствии данных**:
   - Если пользователь спрашивает о товарах, которых нет на бирже (*золото, сырая нефть, автомобили*), о периодах вне диапазона `03.01.2022 – 30.10.2026` (*например, 2021 год или ноябрь 2026 года*), о несуществующих компаниях или атрибутах вне схемы (*ФИО директора, телефон*), агент проверяет БД, видит `0` совпадений и прямо сообщает, что таких данных в реестре нет.
4. **Автоматизированный бенчмарк (`tests/run_eval.py`)**:
   - Решение протестировано на наборе из 30+ вопросов на русском и узбекском языках (простые агрегации, вопросы с подвохом по маркам/сортам/единицам измерения, фонетический поиск компаний, контракты без сделок, просрочки поставки, вопросы на отсутствие данных). Все тесты проходят со статусом `verified=True` и средним временем ответа **3–6 секунд** (при лимите 90 секунд).

## 🚀 Быстрый запуск

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 2. Сборка базы данных DuckDB (если `data/uzex.duckdb` ещё не создана)
Положите CSV-файлы (`deals_2022.csv`..`deals_2026.csv`, `contracts.csv`, `participants.csv`, `brokers.csv`, `usd_rates.csv`) в папку `data/` (или укажите `UZEX_RAW_DIR`) и выполните:
```bash
python src/build_db.py
```
*(База `data/uzex.duckdb` собирается за ~6 секунд).*

### 3. Запуск Веб-сервиса (FastAPI + богатый веб-интерфейс, порт 8000)
```bash
python src/server.py
```
Откройте в браузере: **http://localhost:8000**

Доступные эндпоинты API:
- `GET /` — двуязычный веб-интерфейс (Чат с ИИ-агентом + Аналитический дашборд + Описание архитектуры)
- `POST /api/ask` — потоковый ответ агента (NDJSON: шаги `find_entity`, `run_sql`, верификация и финальный ответ)
- `POST /api/ask_sync` — синхронный JSON-ответ (`{"question": "..."}`)
- `GET /api/stats` — сводная статистика реестра
- `GET /api/dashboard` — полные данные для аналитического дашборда
- `GET /api/health` — проверка готовности сервиса

### 4. Альтернативные интерфейсы (Streamlit и Telegram-бот)
- **Streamlit UI**:
  ```bash
  streamlit run src/app.py
  ```
- **Telegram-бот** (при наличии `TELEGRAM_BOT_TOKEN` в `.env`):
  ```bash
  python src/bot.py
  ```

### 5. Запуск автоматического тестирования (Evaluation Suite)
```bash
python tests/run_eval.py tests/questions_edge.txt -j 2
```
