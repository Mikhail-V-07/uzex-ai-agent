# UZEX AI Agent

AI-ассистент для анализа данных биржевых сделок UZEX. Проект позволяет задавать вопросы на русском и узбекском языках в обычной форме, автоматически формировать SQL-запросы, выполнять их в DuckDB и получать ответы на основе реальных данных.

**GitHub:** [https://github.com/Mikhail-V-07/uzex-ai-agent](https://github.com/Mikhail-V-07/uzex-ai-agent)

---

## 1. О проекте

Цель проекта — создать AI-агента, который помогает анализировать биржевые сделки UZEX без необходимости самостоятельно писать SQL-запросы.

Пользователь задаёт вопрос, например:

- Сколько сделок было заключено в 2025 году?
    
- Какие товары имели наибольший товарооборот?
    
- Как изменялся объём торгов по годам?
    
- Какие товары чаще всего продавались?
    
- 2025-yilda eng yuqori savdo aylanmasiga ega bo‘lgan 5 ta mahsulot qaysilar?
    

Агент должен:

1. Получить вопрос пользователя.
    
2. Передать его языковой модели Gemini.
    
3. Сгенерировать SQL-запрос к базе данных.
    
4. Проверить SQL перед выполнением.
    
5. Выполнить запрос через DuckDB.
    
6. Передать результат Gemini для формирования понятного ответа.
    
7. Показать ответ и, при необходимости, SQL-запрос и таблицу с результатами.
    

**Главный принцип проекта — достоверность.** AI не должен придумывать цифры. Ответы должны строиться на результатах запросов к базе данных.

### Основные компоненты

**1. Streamlit — пользовательский интерфейс**

Файл: `src/app.py`

Отвечает за:

- отображение веб-приложения;
    
- ввод вопросов пользователем;
    
- отображение истории диалога;
    
- отображение ответов AI;
    
- показ SQL-запросов и результатов;
    
- отображение аналитических показателей и графиков.
    

**2. AI Service — логика AI-агента**

Файл: `src/services/ai_service.py`

Это один из главных файлов проекта.

Отвечает за:

- подключение к Gemini API;
    
- передачу вопросов пользователя модели;
    
- генерацию SQL;
    
- проверку SQL-запросов;
    
- выполнение запросов через DuckDB;
    
- формирование ответа на естественном языке;
    
- обработку ошибок и переключение на резервную модель Gemini.
    

В файле предусмотрены функции:

- `generate_sql()` — генерирует SQL-запрос;
    
- `validate_sql()` — проверяет запрос перед выполнением;
    
- `execute_sql()` — выполняет запрос;
    
- `explain_result()` — формирует текстовое объяснение результата;
    
- `ask_database()` — объединяет основные этапы работы агента.
    

**3. Analytics Service — готовая аналитика**

Файл: `src/services/analytics_service.py`

Отвечает за заранее подготовленные аналитические запросы.

Сейчас реализованы методы:

- `get_summary()` — общая статистика;
    
- `get_yearly_turnover()` — товарооборот по годам;
    
- `get_top_products()` — популярные товары по объёму сделок и обороту;
    
- `get_status_statistics()` — статистика по состояниям сделок.
    

В отличие от AI-агента, этот сервис не генерирует SQL через Gemini. Он использует заранее написанные SQL-запросы.

**4. Database — подготовка базы данных**

Файл: `src/database.py`

Отвечает за подключение исходных CSV-файлов и подготовку представлений DuckDB.

Основные представления:

|Представление|Содержание|
|---|---|
|`deals`|Биржевые сделки|
|`contracts`|Контракты|
|`participants`|Участники торгов|
|`brokers`|Брокеры|
|`usd_rates`|Курсы доллара|
|`deals_financial`|Сделки с финансовыми расчётами|

Особенно важно представление `deals_financial`: оно объединяет информацию о сделках, контрактах и курсах валют.

Для финансовых запросов необходимо использовать поле `amount_uzs`, которое приводит суммы к узбекским сумам.

Не следует просто складывать суммы из разных валют.

## 7. Настройка Gemini API

Для работы AI-агента необходим API-ключ Gemini.

Каждому разработчику нужно настроить собственный ключ. Не используйте чужой ключ без разрешения.

Создайте файл `.env` в корневой папке проекта:

```
uzex-ai-agent/
├── .env
├── requirements.txt
└── src/
```

Откройте `.env` в редакторе и добавьте:

```
GEMINI_API_KEY=ВАШ_API_КЛЮЧ

GEMINI_MODEL=gemini-3.6-flash
GEMINI_FALLBACK_MODEL=gemini-3.1-flash-lite
```

Вместо `ВАШ_API_КЛЮЧ` вставьте свой API-ключ.

Получить ключ можно в Google AI Studio:

[https://aistudio.google.com/apikey](https://aistudio.google.com/apikey)

**Внимание:**

- Не добавляйте `.env` в Git.
    
- Не отправляйте API-ключ в общий публичный чат.
    
- Не вставляйте API-ключ непосредственно в Python-файлы.
    
- У каждого разработчика может быть собственный ключ.
    

Файл `.gitignore` уже должен исключать `.env` из Git.

## 9. Как тестировать AI-агента

После запуска проверьте вопросы на русском и узбекском языках.

Примеры:

**Русский:**

- Сколько всего сделок было в 2025 году?
    
- Какие 5 товаров имели наибольший товарооборот в 2025 году?
    
- Сколько сделок было исполнено?
    
- Как менялся товарооборот по годам?
    

**Узбекский:**

- 2025-yilda jami nechta savdo amalga oshirilgan?
    
- 2025-yilda eng yuqori savdo aylanmasiga ega bo‘lgan 5 ta mahsulotni ko‘rsating.
    
- Eng ko‘p sotilgan mahsulotlar qaysilar?
    

При проверке важно смотреть не только на текстовый ответ, но и на SQL-запрос, который сгенерировал Gemini.

Если SQL неправильный, ответ может быть неправильным даже при уверенном объяснении модели.

Для каждого теста желательно проверить:

1. Правильно ли модель поняла вопрос.
    
2. Правильно ли выбрала таблицы.
    
3. Правильно ли сформировала фильтры.
    
4. Правильно ли посчитала суммы и количество.
    
5. Совпадает ли результат с независимым SQL-запросом.
    

Для финансовых показателей используйте `amount_uzs`.

Для анализа только полностью исполненных сделок необходимо учитывать состояние:

```
WHERE "Состояние сделки" = 'Исполнен'
```

Не смешивайте все зарегистрированные сделки с полностью исполненными: это разные показатели.

## 11. Важные правила при разработке

### Работа с базой данных

- Не изменяйте исходные CSV-файлы без согласования с командой.
    
- При добавлении новых полей проверяйте, как они используются в представлениях.
    
- Для денежных расчётов используйте `amount_uzs`.
    
- Учитывайте валюту сделки.
    
- Разделяйте исполненные, частично исполненные и отменённые сделки.
    

### Работа с AI

- Проверяйте сгенерированный SQL.
    
- Не доверяйте ответу только потому, что он звучит убедительно.
    
- Проверяйте спорные результаты отдельными SQL-запросами.
    
- Не допускайте выполнения SQL-команд, изменяющих базу.
    
- При ошибках сохраняйте вопрос пользователя, SQL и текст ошибки.
    

### Работа с Git

Перед началом работы:

```
git pull origin main
```

После изменения файлов:

```
git status
git add .
git commit -m "Описание изменений"
git push origin main
```

Не добавляйте в Git:

- `.env`;
    
- исходные CSV;
    
- локальную базу DuckDB;
    
- виртуальное окружение `venv`;
    
- временные и конфиденциальные файлы.
    

Перед `git add .` всегда проверяйте `git status`.

## 12. Частые проблемы

### Ошибка: `ModuleNotFoundError`

Проверьте, что виртуальное окружение активировано и зависимости установлены:

```
venv\Scripts\activate
pip install -r requirements.txt
```

### Ошибка: `GEMINI_API_KEY is missing`

Проверьте:

- существует ли `.env`;
    
- находится ли он в корне проекта;
    
- правильно ли написано `GEMINI_API_KEY`;
    
- не забыли ли вы вставить API-ключ.
    

### Ошибка: база данных не найдена

Проверьте наличие:

```
data/uzex.duckdb
```

Убедитесь, что CSV-файлы находятся в папке `data`.

### Ошибка: `No such file or directory`

Проверьте, из какой папки запускается команда:

```
pwd
```

Команды запуска приложения нужно выполнять из корневой папки `uzex-ai-agent`.

### Gemini возвращает неправильный SQL

Проверьте:

- SQL-запрос, сгенерированный моделью;
    
- типы столбцов;
    
- используемые представления;
    
- правильность фильтров по датам;
    
- корректность группировки товаров.
    

Если проблема повторяется, добавьте соответствующий пример в тесты.

## 16. Рекомендуемое распределение задач

Чтобы команда могла работать параллельно, предлагается следующее разделение:

|Направление|Основная ответственность|
|---|---|
|Data / Database|Проверка CSV, DuckDB, связей и финансовых расчётов|
|AI / Backend|Gemini, генерация SQL, промпты, валидация и ошибки|
|Analytics|Аналитические запросы, товары, участники, брокеры и графики|
|Frontend|Streamlit, интерфейс, языки и визуализации|
|QA / Testing|Контрольные вопросы, проверка SQL и точности ответов|
|Deployment|Публичное размещение и настройка окружения|

Один участник может отвечать сразу за несколько направлений. Распределение нужно согласовать внутри команды.

## 17. Что сделать в первую очередь завтра

Рекомендуемый порядок работы:

1. Все участники клонируют репозиторий и проверяют локальный запуск.
    
2. Получают исходные CSV-файлы и проверяют базу.
    
3. Проверяют существующую работу AI-агента на русском и узбекском.
    
4. Создают общий список контрольных вопросов.
    
5. Исправляют ошибки генерации SQL и расчётов.
    
6. Улучшают интерфейс и добавляют нужные аналитические возможности.
    
7. Проверяют все ответы по контрольным SQL-запросам.
    
8. Готовят публичную демонстрацию и резервный локальный запуск.
    

**Главный приоритет:** сначала точность данных и ответов, затем новые функции и оформление. Не стоит добавлять много возможностей, пока существующие ответы не проверены на достоверность.
